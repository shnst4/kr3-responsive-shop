# Converse Shop — контрольная работа №3

## Тема

«Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Проект создан на основе КР №1 без Bootstrap. Это учебный сайт: он не отправляет заявки и не фильтрует товары на сервере.

## Структура

```text
kr3-responsive-shop/
├── index.html
├── catalog.html
├── product.html
├── order.html
├── contacts.html
├── css/
│   ├── style.css
│   └── responsive.css
├── images/
├── lighthouse/
├── README.md
└── .gitignore
```

## Чем КР №3 отличается от КР №1

- Адаптивные сетки через Flexbox, Grid и медиазапросы: мобильный экран — базовый; сетки расширяются на 768px и 1100px.
- Шапка и подвал во всю ширину, основное содержимое — по центру с ограничением ширины.
- Адаптивные изображения через `max-width`, а в блоке преимуществ — через `picture`, `source`, `srcset`, `sizes` (использованы два существующих варианта одной фотографии; это _art direction_, а не полноценный набор разрешений).
- Адаптивная таблица: на телефоне прокручивается внутри своего контейнера.
- Доступность: семантические заголовки, `alt`, `label`, `skip-link`, видимый фокус, заголовки таблиц со `scope`, `prefers-reduced-motion`.
- JavaScript и модальное окно удалены: ссылки «Оформить заявку» ведут на отдельную страницу.

## Изображения (важно!)

В папке `images/` должны находиться **пять файлов**, скопированных из старого `img/` в КР №1:

```text
blue_converse-no-bg.png
blue_converse.jpg
item_1_no_bg.png
item_2_no_bg.png
item_3_no_bg.png
```

Код специально ссылается только на эти существующие имена. Не нужны `item_1-320.png`, отдельная папка `scripts` или генерация девяти новых картинок.

## Проверка

1. Открыть через Live Server `index.html`, проверить все пять страниц.
2. Проверить ширины 320, 375, 768, 1024, 1440 пикселей в DevTools.
3. Проверить `Tab` → ссылка «Перейти к содержимому», затем `Enter`, переходы по меню, поля формы, видимый фокус.
4. Открыть `product.html` и убедиться, что таблица не создаёт горизонтальную прокрутку **всей** страницы.
5. Выполнить настоящий аудит Lighthouse → Accessibility для `index.html`, `catalog.html`, `order.html`; сохранить скриншот/отчёт как `lighthouse/report.png` (или HTML-отчёт) и здесь указать фактические результаты. **Отчёт ещё не создан.**
6. Оформить работу через отдельную Git-ветку и Pull Request согласно методичке.

## Ограничения

- Каталог показывает демонстрационные параметры выбора; реальная фильтрация без JS/backend не реализована.
- Форма показывает нативную валидацию `required` и `type="email"`. При корректном заполнении просто перезагружает `order.html`. У её полей нет `name`, поэтому содержимое не попадает в GET-запрос.
- Для полной оптимизации загрузки изображений через набор разрешений потребуется ещё одна уменьшенная версия фотографии. В текущей минималистичной реализации `picture` выбирает одно из двух **уже существующих** изображений по ширине экрана, чтобы избежать лишних файлов.

## Запуск

Откройте `index.html` в браузере или запустите Live Server в VS Code. Никакой сборки и установки зависимостей не требуется.
