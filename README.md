# Converse Shop — контрольная работа №3

## Тема и цель работы

**Тема:** «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Converse Shop — учебный многостраничный сайт каталога обуви Converse. Контрольная работа №3 выполнена **на основе контрольной работы №1**: сохранена предметная область интернет-магазина, но переработаны оформление и структура стилей, добавлены адаптивная вёрстка и улучшения доступности.

**Цель:** научиться самостоятельно адаптировать интерфейс под телефон, планшет и компьютер, а также сделать его удобнее для пользователей клавиатуры и вспомогательных технологий. **Bootstrap и другие CSS-фреймворки не используются.**

Проект демонстрационный: реальная отправка заказов и серверная фильтрация товаров не реализованы.

## Технологии

- **HTML5:** структура пяти страниц, семантические элементы, таблица и форма.
- **CSS3:** оформление, CSS-переменные, Flexbox, Grid, медиазапросы.
- **Mobile First:** базовые стили ориентированы на узкий экран; широкие варианты задаются через `min-width`.
- **Responsive Images:** `max-width: 100%`, `height: auto`, `<picture>` и `<source>` в блоке преимуществ, `loading="lazy"` у карточек товаров.
- **Accessibility (A11y):** клавиатурная навигация, видимый фокус, ссылка пропуска меню, альтернативные описания изображений, корректная разметка форм и таблиц.
- **Chrome DevTools / Lighthouse:** автоматическая проверка категории Accessibility.
- **Git и GitHub:** отдельный репозиторий для КР №3.

**JavaScript в упрощённой версии проекта не используется.**

## Что изменилось по сравнению с КР №1

### 1. Адаптивная вёрстка

В КР №1 основной упор был сделан на HTML-структуру, оформление страниц, Flexbox, Grid, формы и позиционирование. В КР №3 разработана **отзывчивая раскладка**, которая меняется в зависимости от ширины области просмотра (viewport):

- **Менее 768 px:** мобильная версия; карточки и основные блоки расположены преимущественно в одну колонку.
- **От 768 px:** две колонки карточек; на странице товара фотография и описание располагаются рядом; часть полей формы может размещаться в двух колонках.
- **От 1100 px:** три колонки популярных товаров; каталог разделяется на боковые параметры выбора и список товаров.

Используются медиазапросы `@media (min-width: 768px)` и `@media (min-width: 1100px)` в файле `css/responsive.css`.

### 2. Единый контейнер

Шапка и подвал занимают всю ширину окна, а основная информация ограничена центральным контейнером:

```css
.container {
  width: min(calc(100% - 32px), var(--content));
  margin-inline: auto;
}
```

При этом сайт сохраняет небольшие боковые отступы на узких экранах.

### 3. Перестроенная структура CSS

Вместо пяти отдельных файлов стилей страниц из КР №1 используются **два файла**:

- `css/style.css` — общие цвета, шапка, подвал, карточки, формы, таблицы, базовая мобильная раскладка и доступность.
- `css/responsive.css` — дополнительные правила для планшетов и больших экранов и учёт настройки уменьшения анимации.

`style.css` подключается первым, затем `responsive.css`.

### 4. Адаптивные изображения

Изображения ограничены размером своего контейнера (`max-width: 100%`, `height: auto`). Для иллюстрации в блоке преимуществ применён `<picture>`: на узком экране может выбираться существующий JPEG-файл, на других — PNG-иллюстрация. Изображения товаров используют `loading="lazy"` для отложенной загрузки.

### 5. Адаптивная таблица

На странице товара таблица характеристик сохранена в семантическом виде (`<table>`, `<caption>`, `<th scope="col">`, `<th scope="row">`). Она размещена в блоке `.table-scroll` с `overflow-x: auto`: на узком экране при необходимости прокручивается сама таблица, а не вся страница.

### 6. Улучшения доступности

- На каждой странице есть ссылка **«Перейти к содержимому»**, которая становится видимой при фокусе клавиатуры.
- Основная область отмечена `id="main-content"`, а `tabindex="-1"` помогает переводить к ней фокус при переходе по ссылке.
- Для навигации используется `aria-label="Основная навигация"`, а активная страница помечается `aria-current="page"`.
- Изображения снабжены понятными текстами `alt`.
- У полей формы есть связанные `label` и `id`; применены `required`, `type="email"`, `autocomplete`.
- У ссылок, кнопок и полей есть заметная обводка `:focus-visible`.
- Для таблицы используются `<caption>` и заголовочные ячейки со `scope`.
- Настройка `prefers-reduced-motion: reduce` отключает плавную прокрутку для пользователей, предпочитающих меньше движения.

### 7. Упрощение интерактивности

В КР №1 на главной странице были модальное окно «Быстрый заказ» и JavaScript-обработчик. В КР №3 для упрощения проекта они удалены. Теперь ссылки направляют на отдельную страницу `order.html`. Это соответствует основной теме данной работы — HTML, CSS, адаптивность и доступность, а не JavaScript-интерактивность.

## Исправление контрастности для Lighthouse

При первой проверке главной страницы Lighthouse показал **95/100 по Accessibility** и замечание о недостаточном контрасте белого текста ссылок с голубой шапкой сайта.

Чтобы исправить проблему, в `css/style.css` изменена CSS-переменная:

```css
/* Раньше */
--blue: #5c88bd;

/* После исправления */
--blue: #345b85;
```

Шапка использует `background: var(--blue)`, а ссылки меню имеют белый цвет. Новый более тёмный фон улучшает читаемость текста и помогает соответствовать требованию контраста WCAG.

**Повторный Lighthouse-аудит главной страницы (`index.html`, Mobile, Accessibility) показал 100/100.**

Результаты других страниц нужно указать **после повторной проверки**; первоначальные скриншоты с более низкими оценками не являются их итоговыми результатами.

> Результат 100/100 означает прохождение автоматических проверок Lighthouse. Он не доказывает, что проверены все возможные вопросы доступности. Дополнительно проводится ручная проверка клавиатурой.

## Что проверять вручную

1. Открыть все пять страниц и проверить переходы между ними.
2. Проверить ширины **320, 375, 768, 1024 и 1440 px** в DevTools.
3. Убедиться, что вся страница не прокручивается горизонтально; проверить отдельную прокрутку таблицы на телефоне.
4. Нажать `Tab`: первой должна появиться ссылка «Перейти к содержимому»; после `Enter` переход выполняется к `<main>`.
5. Пройти по меню, ссылкам, полям и кнопкам с помощью клавиатуры и убедиться, что фокус хорошо виден.
6. Проверить наличие подписей полей и подсказок браузера при незаполненных обязательных полях.
7. Повторить аудит **Lighthouse > Accessibility** для каждой страницы, сохранить реальные результаты в `lighthouse/`.
8. При необходимости оформить отдельную ветку и Pull Request согласно требованиям методических указаний.
